## Key Decisions

| Decision | Rationale |
|----------|-----------|
| A guard written into a dispatch prompt protects exactly one run (S58, 2026-08-24) | The fixture-exclusion rule that kept the `/bx:arch` dogfood honest existed only in that run's hand-written prompt. `/bx:tests` had the identical exposure and no guard, so its Step 0 resolved the repo's stack from a planted eval fixture's `package.json`. Scope rules belong in a named owner both skills read — `arch/references/scan-exclusions.md`, which governs stack **detection** as well as file scope. (v2.7.0) |
| A negative result needs three states, not two (S58) | "Clean" and "found nothing" are different claims from "the precondition does not exist". `snapshot_heavy` on a repo with no snapshot mechanism is **unavailable**, not clean; reporting it as clean asserts coverage the scan never had. `/bx:tests` gained `coverage_negatives` with unavailable/clean, sharpening the binary version `/bx:arch` shipped in v2.4.0. (v2.8.0) |
| `/bx:save` is model-invocable; the S42 explicit-only flag is reversed (S59, 2026-09-08) | `disable-model-invocation: true` also removes a skill's description from Claude's context, so Claude could never run the end-of-session save and always punted to the user. Proven by a headless A/B: with the flag `false` the skill is visible, with `true` only `/bx:plan` was. `/bx:resume`'s wrap-up step now invokes it. (v2.9.0) |
| `/bx:evolve --fix` only gates same-run findings, and `--full` is bounded to 50 releases (S59) | Fix mode needs `source_excerpt`, which state.json does not store, so a follow-up `--fix` cannot act on the prior run's findings, and the end-of-run watermark advance means the changelog lane never re-emits them; `--full` re-audits only the `gh` window (floor v2.1.203) and the lanes drop deltas bx already handles. The 18 older open findings are therefore reachable only by hand triage. Same-release re-emits under a different capability string enter as new findings (no `applied` branch, no same-URL dedup). |
| Synthetic fixtures bound what a rehearsal can find (S60, 2026-09-28) | Four blind rehearsals passed every outcome check on the Known Issues governor, then one fresh whole-branch review found seven defects, because every fixture entry was a single bold paragraph with an unambiguous lead. Rehearse against entries shaped like real ones, and keep the fresh reviewer: it is the only context that did not write the fixtures. |
| Known Issues is classified by status form, never by the bare word (S60) | "Resolved" means `RESOLVED`, `is/was/now resolved`, or a checked box in the entry's lead; "paths are resolved against cwd" and "not resolved" are open. Doubt resolves to open, because an open entry keeps a trace in CLAUDE.md and a wrongly resolved one leaves none. (v2.10.0) |
| `/bx:evolve` 2.11.0: findings carry their edit, pain points carry a stable id, the changelog lane paginates to its anchor (S61, 2026-10-20) | Carried-forward findings were unactionable because state stored no edit; pain slugs re-hashed on every rewording (8 slugs for 5 concerns); the 50-release window silently lost history. Every open entry now stores `proposed_edit`/`affected_files`/`source_excerpt`/`citation`, `docs/upstream/pain-points.json` gives ids with aliases, Step 3.4 has the `applied` branch + source_url match, and a cap miss records `changelog_gap` instead of advancing past it. Six blind rehearsals on committed fixtures, then two real runs (8 applied). |
| Agent `tools:` specifiers are not enforced — the lists declare intent, the scan instructions are the boundary (S61) | Verified live: an agent declared `Bash(gh:*)` ran `echo` and `git` unblocked, and the sub-agents docs document only bare tool names. The 17 scoped lists are kept as intent; the S43 "least-privilege" claim in evolve SKILL.md, README and architecture.md now says the discipline is prompt-enforced. Command-level limits need `permissions.deny`, which a plugin cannot ship. |
| The `--full` sweep runs before the writer dispatch (S62, 2026-10-21) | A sweep after the single writer dispatch can never be recorded in the session that produced it (S61 wrote its own by hand), and its edits stale the packet's `old` strings. Parts 0.5/2/3/4/1.10/5/6/7 now run first, the session entry carries a `Full sweep:` bullet, Parts 5/6/7.7 count the entry the writer has not appended yet, and 7.3 leaves packet-owned entries alone. First run: this save. (v2.12.0) |
| `affected_capability` is a pinned vocabulary, not lane prose (S62) | Lanes wording capability strings freehand is why `finding_id`s drifted and the `source_url` match had to forgive it. `bx/skills/evolve/capabilities.json` (434 entries, generated by `build-capabilities.py` from frontmatter keys, tools, built-ins, idioms, hook events) is the only legal vocabulary besides `bx:pain/<id>`; Step 0.2 reports drift, `--fix` offers regeneration; the three scan files cite `lane-contract.md` for everything shared instead of restating it. (v2.12.0) |
| Change detection belongs outside the context window (S62) | code.claude.com serves every docs page as `<url>.md`, so a Python probe hashes all 22 allowlisted pages in seconds with zero tokens; the docs lane now reads only changed pages (`watermark.docs_pages`) and re-reads everything only when the pinned inventory's hash changes. It had been spending ~180k tokens re-reading unchanged pages every run. (v2.12.0) |
| The community lane is a discovery feed, not an advisory source (S62) | Degraded in 5 of 6 runs, never fix-eligible, and its real value was the official pages it stumbled on. It now searches official domains and `anthropics/*` maintainer posts for pages the docs allowlist lacks and returns `allowlist_candidates` only (`findings: []`); the docs lane owns the finding once the page is pinned. (v2.12.0) |

## Known Issues / Blockers

**Plugin-versioning sharp edge (S54):** `version` in `bx/.claude-plugin/plugin.json` is the plugin's update cache key — a push that changes `bx/**` without bumping it is never offered to users (`claude plugin update` reports "already at the latest version"). `/bx:save` Part 8 enforces the bump; manual committers follow the README contributors note. History in `CHANGELOG.md`. **The update is shell-only:** `update` has no `/plugin` session form (verified S61 against the CLI reference and live — `/plugin update bx` left the cache stale); refresh with `/plugin marketplace update burak-tools`, then `claude plugin update bx` from a shell, then `/reload-plugins`. Dropping `version` to version by commit SHA was evaluated and rejected S61 (finding `4519c508`).

**Upstream decision log: 1 open, 5 deferred** in `docs/upstream/state.json` (61 entries). Watermark: **changelog 2.1.306 · docs/community 2026-10-21** · 23 page hashes · inventory `45a4793c` (four S62 runs on bx 2.12.x: delta 22/22, `--fix` all-current, delta 5/23, `--fix` all-current; 4 findings applied, `env-vars` pinned). The one open entry is the plugin-eval design item `69ef485d` (out of `--fix` scope: new files + external run); the 5 deferred are pre-2.11.0 legacy entries without stored edits except `5b91feb3` (`.claude/rules/` tier, edit filled S62).

**`/bx:arch` v2 shipped without meeting its own acceptance bar (S58).** Six blind-rehearsal waves ran against the rewritten surfaces; the S56 ≤2 ambiguity bar was not reached (Step 5 15→12→11, report template 24→18→12, scan+rubrics 12→12) and v2.3.0 shipped on the severity curve instead. The residual is formatting conventions and named judgment calls, recorded in the spec's acceptance section rather than waived. **The end-to-end dogfood has since run** (v2.4.0) and found four further defects the rehearsals could not reach.

**bx 2.12.x: four real `/bx:evolve` runs found three defects (fixed in 2.12.1) and left four paths text-only (S62, 2026-10-21).** Fixed by running: the pain-registry threshold spawned duplicate ids for two-word leads (now `min(3, n)`); the validator rejected the pinned `tool:`/`builtin:` vocabulary; a `source_url` match with two stored candidates had no tie-break (larger file overlap used). Still text-only: the changelog lane under `lane-contract.md` (current on every run today), the `--check` drift report and `--fix` regeneration item (no drift occurred), `allowlist_candidates` surviving from a delta run to its `--fix` (carried by hand once), and the probe's full re-read on any inventory change — one renamed token forced a 23-page scan that was narrowed by hand to 5 (new page + pages mentioning the token); the probe should compute the delta from the last committed `capabilities.json` itself. From the v2.10.0 shrinker: multi-paragraph entries, tight bullet lists, the saving-based open phase and archive liveness in rotation remain text-only; the size-based Key Decisions rollup ran for real this save.
