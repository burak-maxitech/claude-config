| `/bx:evolve` 2.11.0: findings carry their edit, pain points carry a stable id, the changelog lane paginates to its anchor (S61, 2026-10-20) | Carried-forward findings were unactionable because state stored no edit; pain slugs re-hashed on every rewording (8 slugs for 5 concerns); the 50-release window silently lost history. Every open entry now stores `proposed_edit`/`affected_files`/`source_excerpt`/`citation`, `docs/upstream/pain-points.json` gives ids with aliases, Step 3.4 has the `applied` branch + source_url match, and a cap miss records `changelog_gap` instead of advancing past it. Six blind rehearsals on committed fixtures, then two real runs (8 applied). |
| Agent `tools:` specifiers are not enforced — the lists declare intent, the scan instructions are the boundary (S61) | Verified live: an agent declared `Bash(gh:*)` ran `echo` and `git` unblocked, and the sub-agents docs document only bare tool names. The 17 scoped lists are kept as intent; the S43 "least-privilege" claim in evolve SKILL.md, README and architecture.md now says the discipline is prompt-enforced. Command-level limits need `permissions.deny`, which a plugin cannot ship. |
| The `--full` sweep runs before the writer dispatch (S62, 2026-10-21) | A sweep after the single writer dispatch can never be recorded in the session that produced it (S61 wrote its own by hand), and its edits stale the packet's `old` strings. Parts 0.5/2/3/4/1.10/5/6/7 now run first, the session entry carries a `Full sweep:` bullet, Parts 5/6/7.7 count the entry the writer has not appended yet, and 7.3 leaves packet-owned entries alone. First run: this save. (v2.12.0) |
| `affected_capability` is a pinned vocabulary, not lane prose (S62) | Lanes wording capability strings freehand is why `finding_id`s drifted and the `source_url` match had to forgive it. `bx/skills/evolve/capabilities.json` (434 entries, generated by `build-capabilities.py` from frontmatter keys, tools, built-ins, idioms, hook events) is the only legal vocabulary besides `bx:pain/<id>`; Step 0.2 reports drift, `--fix` offers regeneration; the three scan files cite `lane-contract.md` for everything shared instead of restating it. (v2.12.0) |
| Change detection belongs outside the context window (S62) | code.claude.com serves every docs page as `<url>.md`, so a Python probe hashes all 22 allowlisted pages in seconds with zero tokens; the docs lane now reads only changed pages (`watermark.docs_pages`) and re-reads everything only when the pinned inventory's hash changes. It had been spending ~180k tokens re-reading unchanged pages every run. (v2.12.0) |
| The community lane is a discovery feed, not an advisory source (S62) | Degraded in 5 of 6 runs, never fix-eligible, and its real value was the official pages it stumbled on. It now searches official domains and `anthropics/*` maintainer posts for pages the docs allowlist lacks and returns `allowlist_candidates` only (`findings: []`); the docs lane owns the finding once the page is pinned. (v2.12.0) |
| `quick_win` is a closed set, not a confidence level (S63, 2026-10-21) | The `/bx:clean` content review found 14 defects by reading; re-running the three committed evals found the 15th: the tag had no definition, so scanners marked whole modules `quick_win: true` and only the orchestrator's hand reconciliation stood between a confident scanner and an unconfirmed `--fix` deletion. Four classes carry the tag — empty file, backup suffix, 5+ line commented block, carve-out-clean unused import — and everything else is one confirmation. A regression tie (42/42 both versions) was still worth the run. (v2.13.0) |
| A directory scope narrows what is reported, never where references are searched (S63) | `/bx:clean src/payments/` grepped only the scoped folder for dependency uses, so every dep the rest of the app used read as unused — and the scope was never passed to the agents at all. File-level categories report inside the scope with repo-wide reference search; manifest-level categories (deps, vulns, config) run under a scope only when it is a workspace root, otherwise they are skipped and the dashboard says why. (v2.13.0) |
| An assertion is anything that fails the test on a regression; only no-op tests are deletable (S65, 2026-10-26) | Literal T01 rules offered 12 real pytest tests whose only checks were `mock.assert_called*` for deletion, and the one genuine assertion-free test was a deliberate no-raise check. The catalog now defines assertions in one place (mock verification, `getBy*`, Playwright actions, helpers) and splits T01 into T01a no-op (deletable, suite-verified on a branch) and T01b implicit no-raise (rewrite, never delete). (v2.13.3) |
| A test-upkeep skill must shrink suites, not only grow them (S65) | No file-level orphans exist in either repo — compilers and imports enforce that — but tests keep dead code alive (maxitech `build_reply_all_recipients`: 5 tests, zero production callers, live replacement untested), and horowell's test/source LOC rose 0.49 → 0.88 with almost no parameterization. 2.14.0 adds `life_support` and `consolidate` findings, a third headline, and a suite-verified `--fix` that can apply them. |
| A merge or deletion is guarded by the case count, not by a green suite (S65, 2026-10-26) | On a throwaway clone, a consolidate merge that dropped one of three rows left the file green; only the count check (6 expected, 5 found) caught it. `--fix` now requires a deletion to drop the count by exactly what it removed and a merge to leave it unchanged, and reverts restore a per-item snapshot because `git checkout -- <file>` would undo earlier verified items. (v2.14.0) |
| A brief must survive its own first edit: name tests by anchor and runs by saved folder, never by line or temp-dir cluster id (S66, 2026-10-28) | Horowell S257 could resume a plan only by grepping another session's scratchpad, and its line numbers went stale after the first merge. `run.py --save-to` keeps the run in a git-excluded `<repo>/.bx/tests/<date>/`, clusters carry a sha1 key of their anchors, and `--fix` locates by anchor. (v2.14.1) |
| Coverage through an unmocked caller is `indirect`, not a gap — and a caller whose test mocks the symbol's module does not count (S66) | Mock-only and untested statuses flagged functions S257 found well tested through another export; the naive fix then counted handlers whose tests patch service factories by string. Module-mock facts from the parsed tests are the filter (maxitech 81 → 20, sample verified). (v2.15.0) |
| `/bx:save` loads `--full` instructions only on `--full`, and finds the session's commits from the last commit that wrote `docs/STATUS.md` (S67, 2026-10-28) | The everyday save read 75 KB of instructions to use 28 KB of them. A `Last Updated` date cutoff re-counted the earlier saves' commits whenever a day had more than one save (S65: three saves on 10-26). (v2.15.1) |

**`/bx:clean` has run on two real repos (S64, 2026-10-23).** Two report-only runs on real code: maxitech-concierge (Python) found 6 defects, fixed in 2.13.1, and horowell (Next.js 16, 1,780 files) found 10, fixed in 2.13.2. Two leftovers from a late rerun: test-only line extents are sometimes wrong (`18-19` for a function whose 14-line doc comment was claimed included; one `lines: unknown` on a Drizzle table), which `--dry-run` would show; and very long De-export output overflows despite the 50-line cap (list cut off, total estimated).
